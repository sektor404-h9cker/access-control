# Сервер проходной SMZ

Один компьютер в локальной сети хранит единственную базу `data/smz.db`. Браузеры к файлу базы не подключаются. Агент камер тоже не открывает SQLite: он отправляет кадры на сервер по токену.

Локальный просмотр в браузере сохранён. Он используется, только пока агент проходной не запущен. Закрытие вкладки останавливает только этот браузерный просмотр.

## Что уже разделено

- Сервер: сотрудники, шаблоны, посещаемость, настройки, роли и журнал.
- Агент: открывает USB-камеру через ffmpeg и отдаёт JPEG на сервер.
- Зритель: авторизованная страница берёт последний кадр с сервера и не вызывает `getUserMedia`.

Второй компьютер видит тот же кадр, потому что физическую камеру открывает только агент. Пока на сервере нет отдельного детектора лица, статус видео будет «AI недоступен». Порог SFace 0.363 не изменён. Автоматическая официальная отметка не включается. Повторный кадр после переподключения не создаёт посещаемость: маршрут кадра не вызывает распознавание.

## Один удалённый поток

1. На компьютере с камерой: `npm run gate:token`. Файл `data/gate.token` не коммитится и не печатается.
2. Скопируйте `data/gate-agent.example.json` в `data/gate-agent.json`.
3. Для CAM-01 оставьте `camera-entrance` и индекс устройства. Второй пост добавляется отдельной строкой с другим устройством. Один и тот же индекс на две камеры агент не запустит.
4. `npm run gate:agent`.

macOS захватывает камеру через AVFoundation. Windows — через DirectShow, имя устройства в поле `device`. Служба Windows в Session 0 камеру и динамики не видит, поэтому автозапуск сделан задачей в сеансе вошедшего пользователя:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\install-gate-task.ps1
```

Этот сценарий на Windows-компьютере не проверялся.

Остановка владельцем пишет `gate_desired=stopped`, попадает в журнал `gate.control` и заставляет агент освободить камеру. Обычный пользователь кнопку не видит, а сервер отклоняет чужую команду.

«Кадры идут» появляется только когда агент жив, кадры свежее 5 секунд и AI готов. Живой агент без кадров показывает «Нет кадров».

## Адрес для другого компьютера

Разработка остаётся на `127.0.0.1:3000`. Для локальной сети после сборки:

```bash
npm run build
npm run start:lan
SMZ_LAN=1 npm run lan:https
npm run lan:address
```

`start:lan` слушает все интерфейсы по HTTP только на порту приложения. `lan:https` выпускает локальный сертификат в `data/certs` и принимает HTTPS на порту 3443. Сертификат самоподписанный: на втором компьютере браузер покажет предупреждение, пока сертификат не добавлен в доверенные. Адрес входа — строка, которую печатает `npm run lan:address`, обычно `https://<адрес-в-сети>:3443`.

Камера не имеет отдельного публичного адреса. `/api/gate/live/...` отвечает только вошедшему пользователю с правом просмотра. Токен агента этот адрес не открывает.

Извне локальной сети используйте VPN до этой сети. Порт камеры в интернет не публикуется.

## Резервная копия и восстановление

`npm run backup` уже кладёт в папку копии базу, фотографии и `biometric.key`. Ключ нужен для чтения биометрических шаблонов. Без него база открывается, а шаблоны — нет.

Восстановление:

1. Остановите агент и сервер, чтобы файл базы не был открыт на запись.
2. Сохраните текущие `data/smz.db` и `data/biometric.key` отдельно.
3. Подставьте `database.db` из копии как `data/smz.db`, `biometric.key` как `data/biometric.key` с правами только для владельца, фотографии — в `data/photos`.
4. Проверьте файл: `sqlite3 data/smz.db "PRAGMA integrity_check;"`. Ожидается `ok`.
5. Запустите сервер. Агент запускайте только после сервера. Второй процесс не должен открывать базу на запись.

Существующие сотрудники, роли и посещаемость этой настройкой не удаляются. Новая схема не создавалась.

## Диагностика

- Агент молчит: процесс `npm run gate:agent` не запущен или не достучался до `server` в `data/gate-agent.json`. Смотрите `data/gate-agent.log`.
- Нет кадров: агент жив, но ffmpeg не открыл устройство. На macOS список устройств: `ffmpeg -f avfoundation -list_devices true -i ""`. На Windows: `ffmpeg -list_devices true -f dshow -i dummy`.
- Страница другого компьютера не открывается: сервер всё ещё на `127.0.0.1`, либо HTTPS-прокси не запущен, либо компьютеры в разных сетях.
- Звук на проходной: агент умеет проиграть короткий сигнал через `afplay` на macOS и SoundPlayer в интерактивном сеансе Windows, только когда сервер вернёт событие. Сейчас кадр не запускает распознавание, поэтому сигнал распознавания на динамик проходной не отправляется. Воспроизведение на Windows не проверялось.

## Что не считать проверенным

На этой машине нет второго компьютера, второй USB-камеры и Windows. Автозапуск, перезагрузка Windows, звук динамика проходной и просмотр с другого ПК остаются непроверенными, пока их не пройдут на целевом оборудовании.
